# The Wild Oasis

Cabin booking app. Next.js App Router frontend, Convex backend, Better Auth for auth.

Everything below the two managed blocks above is hand-written. The blocks are
regenerated by `next dev` and `convex ai-files install` — leave them alone and commit
their churn along with your work.

## Documentation

**`docs/` is the source of truth for how this project is built and why.** Read the
index before starting work — it is short, and it tells you which document covers the
area you are touching.

- **[`docs/README.md`](docs/README.md)** — index of every document, and the convention
  for adding new ones.

Load the document that matches your task rather than reading all of `docs/`. At minimum:

## Commands

Bun is the package manager. Do not use npm/pnpm/yarn.

| Command                 | What it does                                         |
| ----------------------- | ---------------------------------------------------- |
| `bun run dev`           | Next dev server (also rewrites the block above)      |
| `bunx convex dev`       | Convex dev server — keep running while working       |
| `bun run check`         | Prettier check + ESLint                              |
| `bun run typecheck`     | `tsc --noEmit`                                       |
| `bun run test`          | Vitest, both projects (`convex` + `frontend`)        |
| `bun run test:e2e`      | Playwright — builds first, runs against `next start` |
| `bun run build`         | Production build                                     |
| `bun run auth:generate` | Regenerate `convex/betterAuth/schema.ts`             |

**Before declaring work done:** `bun run check && bun run typecheck && bun run test && bun run build`.
Add `bun run test:e2e` when you touched routing, layout, or rendered output.

## Rules that are easy to get wrong

- **Env vars live in two stores.** `.env.local` holds the Next.js/`NEXT_PUBLIC_*` values;
  Better Auth secrets belong to the Convex deployment (`bunx convex env set`) because the
  auth instance runs inside Convex. Adding a var is a four-file change — see
  `docs/01_PROJECT_SCAFFOLD.md` §4.
- **`better-auth` is pinned exactly to `1.6.15`.** No caret. Newer patches break the
  provider's types. Bump it only together with `@convex-dev/better-auth`.
- **Changing `createAuthOptions` requires regeneration:** `bun run auth:generate`, then
  `bunx convex dev --once`.
- **Generated files are committed but never hand-edited:** `convex/**/_generated`,
  `convex/betterAuth/schema.ts`.
- **Convex functions always declare `args` validators.** Anything not meant for the public
  internet is `internalQuery`/`internalMutation`/`internalAction`. Authorization is
  enforced inside the function, never by the caller.
- The root layout is **async and dynamic** (it awaits `getToken()`), so every route
  renders on demand.

## Conventions

House style — naming, feature slices, domain modeling, comments, testing, git — is
`docs/02_CODING_GUIDELINES.md`. It is not summarized here; a second copy would drift.

Only what is specific to this repo:

- Feature code goes in `features/<feature>/` at the repo root, following the slice layout
  in `02` §6. There is no `src/` — Next does not scaffold one, and `@/*` aliases from the
  root. `app/` route files stay thin and render a screen from a slice.
- `components/ui/` is shadcn-owned (Base UI primitives, not Radix); `components/` holds
  what is shared across features.
- A new top-level source directory must be added to the Vitest `include` and coverage
  globs, or its tests silently never run.
- Prettier + ESLint own formatting, not Biome — see `01_PROJECT_SCAFFOLD.md` §13 for why
  this repo diverges. Never hand-format; run `bun run format`.
- Tailwind v4 — no `tailwind.config`. Theme tokens are in `app/globals.css`.
- Branches: `dev` is the working branch, `main` is the release branch.
